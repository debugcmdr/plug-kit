## 一、项目定位与技术栈

**PlugKit = 工具市场外壳**：主程序零业务功能，视频下载/格式转换等能力全部以插件（CLI + HTML UI）形式存在，按需安装。零后端分发（GitHub Raw 清单 + Release zip）。

| 层 | 技术 | 规模 |
|---|---|---|
| 桌面壳 | Tauri 2 + Rust | 16 模块，约 3300 行 |
| 前端 | Vue 3.4 + naive-ui + Vite 5 | 8 组件（无路由、无状态库） |
| 插件 | Python CLI + 原生 HTML | download（yt-dlp）、convert（ffmpeg） |
| 分发 | GitHub Raw JSON + Release zip | 零后端 |
| 测试 | Rust 集成测试 + vitest 单测 | CI 已接入清单校验 |

核心数据流：市场清单（GitHub Raw + 兜底快照 + 内存缓存 5min）→ 安装（SHA256 + Zip-Slip + 可选签名验签 + 原子替换）→ 运行（子进程 stdout JSON 协议 → 任务中心闭环 → 进度事件回推 iframe）。

## 四、新功能设计建议（简洁）

1. **任务中心增强**（建议最优先）：并发上限与历史清理已落地，剩余——优先级队列（重要任务插队）。
2. **工作流编排**：插件间组合（下载 → 转码 → 压缩），复用共享依赖链，任务以 DAG 调度。
3. **市场详情页**：截图、安装量、更新时间、版本历史、评分——让市场从"清单"变成"商店"。
4. **系统集成**：全局快捷键唤起、文件拖拽直达对应插件、右键"用 PlugKit 打开"（需先恢复 manifest 能力声明，此前已删除 fileAssociations）。
5. **数据安全**：插件配置（configs/）可选加密，密钥从系统 keychain 派生。
6. **性能**：naive-ui 按需引入 + chunk 拆分，主包从 1.44MB 降到 ~300KB。
