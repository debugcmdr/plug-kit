# PlugKit 插件开发指南

> PlugKit | 工具市场 — 为创作者准备的插件协议文档。

一个 PlugKit 插件 = **一个 CLI 可执行文件 + 一个 HTML 界面**。插件通过标准 stdout JSON 协议与主程序通信,支持任意语言(Python / Rust / Go / Node…)。

## 目录结构

```
plugin-repo/
├── manifest.json              # 运行时清单(主程序读取)
├── tool/
│   ├── plugkit-<id>           # CLI 可执行文件
│   └── index.html             # iframe UI(可省略,纯 CLI 也可)
└── README.md
```

## manifest.json

| 字段 | 说明 |
|------|------|
| `id` | 插件唯一标识(与仓库一致,如 `download`) |
| `name` / `description` | 市场展示用 |
| `version` | semver,如 `0.1.0` |
| `platforms` | 支持平台:`windows-x64` / `macos-arm64` / `macos-x64` / `linux-x64` |
| `dependencies` | 共享依赖:`{"yt-dlp": ">=2024.01.01", "ffmpeg": ">=6.0"}`(由主程序统一提供,**固定版本** + 校验和验证,插件**禁止自带**) |
| `bridgeVersion` | 桥接 SDK 版本约束,固定 `">=1.0.0"` |
| `minAppVersion` | (可选)要求主程序最低版本,如 `"0.2.0"`;主程序过旧时拒绝安装并提示升级 |
| `entry` | `{ "type": "cli", "executable": "...", "toolDir": "tool" }` |
| `commands` | CLI 命令定义:`{ "命令名": { "stdinArgs": [...], "output": "json" 或 "progress+json" } }` |
| `ui` | `{ "type": "iframe", "html": "index.html" }`(可选) |

## CLI stdout 协议

stdout **每行一个 JSON 对象**,禁止多行合并。

### 进度消息(`progress+json` 模式)

```json
{"type":"progress","percent":45.5,"speed":"2.3MB/s","eta":"30s","message":"下载中...","file_name":"a.mp4","output_path":"/path/to/out/a.mp4"}
```

`percent` 允许 `null`(无百分比的任务)。**必须 `flush=True`**,否则主程序读不到实时进度。

可选字段(任务中心据此展示,建议携带):
- `file_name`:任务处理的文件名(任务中心显示)。
- `output_path`:输出文件或目录路径(任务中心「打开输出文件夹」按钮使用)。

### 结果(任务结束最后一行)

```json
{"type":"result","success":true,"data":{...}}
```

### 错误

```json
{"type":"error","code":"PLUGIN_ERROR","message":"下载失败：服务器返回 404"}
```

**错误 message 约定**(统一格式,任务中心/日志页直接展示):
`原因。操作建议 ｜ 详情: <底层报错原文> (退出码 N)`。错误码保持稳定,便于用户识别与排查:

```json
{"type":"error","code":"NETWORK_ERROR","message":"网络连接失败。请检查网络后重试 ｜ 详情: [Errno -2] Name or service not known (yt-dlp 退出码 1)"}
```

错误会按三级展示,插件内只需提供完整 message,主程序自动分层:

| 层级 | 位置 | 内容 |
|------|------|------|
| 最简 | 插件 UI | 主程序截断显示原因段(「｜」前),插件无需处理 |
| 中等 | 任务中心 | 完整 message |
| 最详细 | 日志页 | TASK_ERROR 可展开条目(错误码 + message + task_id) |

### macOS cookies 权限

读取浏览器 cookies 受系统「完全磁盘访问」限制(Safari 等沙盒浏览器)。插件发现
`Operation not permitted` 类错误时,可用桥接 API 引导用户一键打开授权面板:

```js
await MT.system.openPermissionSettings();  // 直达「完全磁盘访问」设置页(macOS)
```

## iframe UI

插件 UI 是一个 HTML 文件,主程序通过 `plugkit://plugin/{id}/tool/index.html` 加载,**自动注入 bridge SDK**(`window.MT` / `window.PlugKit`)。

```html
<script>
  const MT = window.MT || window.PlugKit;
  // 调用插件命令
  const r = await MT.invoke('download', { url: '...', quality: '1080p' });
  // 订阅进度
  MT.onProgress((evt) => { console.log(evt.data.percent); });
  // 并发任务的进度过滤:invoke 时自备 task_id,onProgress 里按它过滤归属,
  // 否则多任务并发时进度事件会串台(事件是 iframe 级广播)。
  const taskId = crypto.randomUUID();
  MT.onProgress((evt) => { if (evt.data.task_id && evt.data.task_id !== taskId) return; /* 本任务进度 */ });
  await MT.invoke('download', { url: '...', task_id: taskId });
  // 插件配置(独立于主程序设置)
  await MT.config.set('default_quality', '720p');
  const q = await MT.config.get('default_quality');
  // 日志(写入主程序统一日志目录)
  MT.log.info('开始下载');
  // 任务:由 MT.invoke 自动创建(带 URL 去重——活跃任务不重复创建,终态允许重新解析)
  // 任务控制:取消 / 暂停 / 恢复(暂停为真实暂停,恢复后从原进度继续)
  await MT.task.cancel(task_id);
  await MT.task.pause(task_id);
  await MT.task.resume(task_id);
</script>
```

## 共享依赖注入

插件在 manifest 声明 `dependencies`,主程序运行时通过**环境变量**注入路径:

- `PLUGKIT_FFMPEG` → ffmpeg 可执行路径
- `PLUGKIT_FFPROBE` → ffprobe 可执行路径
- `PLUGKIT_YT_DLP` → yt-dlp 可执行路径(注意:依赖名连字符转下划线,`yt-dlp` → `YT_DLP`)

获取优先级:**系统 PATH → 共享缓存 → 自动下载**(固定版本 + sha256 校验)。当前内置依赖:yt-dlp / ffmpeg / ffprobe。插件 CLI 应优先使用环境变量,找不到时回退到系统 PATH。

## 开发流程

### 主程序开发

```bash
# 终端 1: 前端热更新 + Rust 后端(dev 模式)
npm run tauri dev

# 终端 2: 插件文件变化自动同步到 ~/.plugkit/plugins/
npm run dev:watch
# 或单独监听某个插件:
npm run dev:watch download
```

- **Vue 前端**：`npm run dev` 启动 Vite，改 `.vue`/`.ts` 即时刷新
- **Rust 后端**：`npm run tauri dev` 监听 `src-tauri/src/` 变化自动重编译
- **插件 UI / CLI**：`npm run dev:watch` 每 1 秒轮询 `plugins/` 目录，变化时自动 `rsync` 到 `~/.plugkit/plugins/`，iframe 刷新即生效，无需重启应用

### 插件开发

插件在 `plugins/<id>/tool/` 下编写，同步到 `~/.plugkit/plugins/<id>/` 后主程序自动读取。

```bash
# 手动同步一次(开发调试用)
./scripts/sync-plugins.sh <plugin_id>
# 例: ./scripts/sync-plugins.sh download
```

### 环境变量

| 变量 | 说明 |
|------|------|
| `PLUGKIT_MANIFEST_URL` | 市场清单 URL（覆盖默认 GitHub Raw）|
| `PLUGKIT_MIRRORS` | 下载镜像前缀列表（逗号分隔，覆盖内置候选池）|
| `PLUGKIT_REPO` | 主仓库地址（`org/repo`，发布脚本用，覆盖默认 `debugcmdr/plug-kit`）|
| `PLUGKIT_SIGN_KEY` | 插件签名私钥路径（`package-plugins.sh` 打包时自动签名）|
| `PLUGKIT_FFMPEG` | ffmpeg 可执行路径 |
| `PLUGKIT_YT_DLP` | yt-dlp 可执行路径(依赖名连字符转下划线) |
| `PLUGKIT_FFPROBE` | ffprobe 可执行路径 |

### 测试

```bash
# Rust 单元测试 + 集成测试
cd src-tauri && cargo test

# 前端类型检查 + 构建
npm run build

# 前端单元测试(vitest)
npm run test:unit

# 市场清单一致性校验(发布前/CI)
./scripts/verify-manifests.sh

# 插件协议测试(需先同步插件到 ~/.plugkit/plugins/)
cargo test --test tool_runner_e2e
```

## 发布流程

1. 编写插件(用模板仓库起步)
2. 本地验证:`python3 tool/plugkit-<id>.py --help`
3. 创建 GitHub 仓库 `<你的组织或用户名>/plugkit-<id>`(内置插件随主仓库 [debugcmdr/plug-kit](https://github.com/debugcmdr/plug-kit) 分发)
4. 打 tag 触发 CI 构建各平台 zip
5. 上传 Release(命名 `plugkit-<id>-{platform}.zip`)
6. 内置插件:在主仓库运行 `./scripts/package-plugins.sh <tag>` 自动生成
   `market/plugins.json` 条目(版本/sha256/size 由脚本写入,勿手工编辑);
   第三方插件:在自己的市场清单(任意 GitHub Raw JSON)中登记。

## 安全边界

- 插件在受限子进程中运行,每个任务有独立工作目录 `~/.plugkit/tmp/{plugin_id}/{task_id}/`,任务结束后自动清理
- 主程序强制 SHA256 + Zip-Slip 校验,插件包无法越界写入
- 插件包支持 Ed25519 签名验签(可选):配置官方公钥后,未签名插件拒绝安装
- 插件 UI 在 iframe sandbox 中(无 same-origin 权限),且 HTML 被注入严格 CSP:
  禁止插件页面发起网络请求(connect-src 'none'),网络能力一律通过桥接 SDK 走主程序
- 插件应遵守 stdout 协议,进度消息及时 flush
