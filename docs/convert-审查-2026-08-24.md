- **审查日期**：2026-08-24
- **审查范围**：`plugins/convert/`（manifest + tool/plugkit-convert CLI + tool/index.html UI）+ `tests/unit/test_convert_cli.py`
- **审查基线**：当前 dev 分支（v0.5.0：视频模块左右分栏、音频提取独立操作、plugkit:// 协议 no-store 已修）

## 一、现状概览

| 维度 | 状态 |
|---|---|
| 类别 | 视频 / 音频 / 图片（输入白名单 18/13/12，输出 10/9/8 + 音频提取 mp3/m4a/wav） |
| 视频模块 | 左右分栏：格式转换（独立按钮）+ 音频提取（独立按钮），"点哪个执行哪个" |

## 二、已有功能问题

### P1（应修复：影响正确性 / 输出质量）

| # | 位置 | 问题 | 影响 | 修复方案 |
|---|---|---|---|---|
| C1-1 | `build_audio_cmd` wav 分支 `-ar 44100` | **wav 输出强制降采样到 44.1kHz**：48kHz/96kHz 源被降采样。wav 是"无损"格式，降采样损失不可逆，违背用户选 wav 的语义 | 高保真场景输出劣化 | 去掉 `-ar 44100`（ffmpeg 默认保留源采样率）；仅当源采样率异常（如 <8kHz）时无需处理 |
| C1-2 | `convert_video` gif 分支 `fps=10,scale=480:-1` | 参数写死：长视频转 gif 帧数爆炸（10fps × 长时长），且固定 480 宽不可调，无时长提示 | 长视频转 gif 体积巨大 / 用户不可控 | ① UI 加 fps/宽度选项（见新功能 C4）；② 或至少检测输入时长 >60s 时给提示；③ scale 改 `-2` 保偶 |
| C1-3 | `convert_video` webm 分支只查 `libvpx-vp9` 不查 `libopus` | `-c:a libopus` 若编码器缺失，ffmpeg 裸报错（无 ENCODER_MISSING 友好提示） | 与 mp4/heic/avif 的防护不对称，诊断体验差 | 同一次 `has_encoder` 检测同时查 vp9 与 libopus，任一缺失给 ENCODER_MISSING 并列出可用项 |
| C1-4 | `convert_video` ts/m4v 分支 `-c:v copy` | 源编码与容器不兼容（如 vp9→m4v、av1→ts）时 ffmpeg 报错，且无降级 | 部分输入必失败 | copy 失败时降级 libx264 转码重试（先试 copy，失败回退转码）；或直接统一 libx264 转码（体积增大，但 ts/m4v 属低频格式，可接受转码） |

### P2（优化项：机制 / 能力缺口）

| # | 位置 | 问题 | 影响 | 修复方案 |
|---|---|---|---|---|
| C2-1 | 提取音频无"原样"模式 | 提取恒重编码 192k（mp3/m4a），用户只想"把音轨抠出来"时：① 无损源（flac 音轨）被压成有损；② 速度慢 | 高保真提取场景能力缺口 | 音频提取下拉加第 4 项"保持原格式（无损复制）"：ffprobe 探测源音轨编码 → 映射扩展名 → `-c:a copy` 快速封装（零损耗零转码）；详见新功能 C7 |
| C2-2 | `probe()` 死接口 | UI 硬编码 FORMATS，probe 无消费方；ffmpeg 缺失要等点转换才报 FFMPEG_MISSING | 装完插件无依赖状态反馈；probe 字段漂移无校验 | ① UI 进页面调用 probe：ffmpeg 缺失给页内提示（而非转换时才炸）；② 用 probe 的 has_encoder 结果动态禁用不可用格式（webm/avif 等） |
| C2-3 | manifest 未声明 ffmpeg 构建偏好 | 依赖机制按 dep_manifest 下载 pinned 构建（macOS 的 evermeet 构建缺 AV1/webp 等编码器），convert 靠 has_encoder 降级"能用但缺能力" | macOS 用户部分格式不可用且无安装期提示 | ① manifest dependencies 增加构建偏好字段（如 `"prefer": "full"`），外壳安装依赖时优先完整构建（需外壳支持该字段，属跨插件机制变更）；② 或维持降级 + 在 UI 提示"完整 ffmpeg 可解锁更多格式" |
| C2-4 | avi/mpg/flv 分支无 `-preset` | 走默认 preset，行为不一致（其余分支显式 medium） | 一致性小瑕疵 | 统一补 `-preset medium`（或与 preset 参数联动） |

## 三、新功能建议（按价值/复杂度排序）

### C4. 视频压缩预设（价值：高 ｜ 复杂度：低-中）
- **场景**：用户高频诉求——"把 4K 视频压小发微信/上传"。
- **方案**：视频分类左侧「格式转换」下拉下加一档 **「mp4（H.265）· 小体积」已存在**；扩展为三档 crf 预设：H.264 默认（crf 23）/ H.265 推荐（crf 23）/ H.265 高压缩（crf 28 + 可选 scale 1080p 上限）。
- **改动**：CLI `convert_video` 加 `--crf` 透传（参数已存在，仅 UI 暴露）；UI formatVideo 条目加 `data-crf`/`data-scale`。复用现有 data-codec 模式，机制零新增。

### C5. 视频截取片段（价值：中-高 ｜ 复杂度：中）
- **场景**：剪一段发人/收藏。
- **方案**：视频分类加"起止时间"两个输入（支持 `HH:MM:SS` 与秒），非空时 CLI 加 `-ss <start> -to <end>`（先 -ss 再 -i 快速 seek）。单文件场景价值最高，批量时时间对全部文件生效（文案提示）。
- **改动**：CLI convert_video 加 `--start/--end`；UI 视频模块左侧卡片加两个输入框。注意：与批量语义需明确（全批同时间戳）。

### C6. GIF 参数化（价值：中 ｜ 复杂度：低）
- 接 C1-2：UI 加 fps（5/10/15）与宽度（320/480/720）下拉，CLI 参数化 `-vf fps=X,scale=W:-2`。防长视频体积爆炸（加时长>60s 提示）。

### C7. 音频提取"保持原格式"（价值：中-高 ｜ 复杂度：中）
- 接 C2-1：音频提取下拉第 4 项"原样（无损复制）"。CLI 用 ffprobe 探测源音轨 codec → 映射输出扩展名（aac→.m4a、mp3→.mp3、opus→.opus、flac→.flac、vorbis→.ogg…），`-c:a copy` 快速封装，零转码零损耗。
- **收益**：① 无损音轨无损提取；② 提取速度近实时（不重编码）；③ 覆盖任意源格式（呼应"无论内置什么格式"）。
- **注意**：映射表需覆盖主要编码器；探测失败时回退重编码 mp3。

### C8. WebM AV1 编码选项（价值：中 ｜ 复杂度：低）
- webm 分支 libvpx-vp9 慢；libsvtav1 快且压缩好。UI 加「webm（AV1）」选项（has_encoder 探测 libsvtav1，缺失降级 vp9/提示）。注意 AV1 解码兼容性（老设备不支持）。

### C9. 拖拽添加文件（价值：中 ｜ 复杂度：低）
- 插件页支持拖拽文件到卡片区域（外壳 webview 拖放 + 获取路径需桥接支持——**需先确认外壳是否暴露拖放路径能力**；若无，属外壳机制变更，跨插件）。

### C10. 转换前输入信息展示（价值：中 ｜ 复杂度：中）
- 选中文件后调 ffprobe 显示时长/分辨率/编码（信息面板），帮助用户判断格式/压缩需求。属信息层增强，不动转换逻辑。

## 四、优先级建议（执行批次）

| 批次 | 内容 | 理由 |
|---|---|---|
| **批 1（正确性）** | C1-1 wav 采样率 / C1-3 webm opus 防护 / C1-2 gif 提示 / C1-4 ts/m4v copy 降级 | 输出质量与诊断正确性，改动小、无 UI 结构变化 |
| **批 2（能力）** | C7 原样提取音频 / C4 压缩预设 / C6 gif 参数化 | 直接兑现"提取任意音轨 + 控制体积"的核心场景，复用现有参数机制 |
| **批 3（体验/清洁）** | C2-2 probe 联动 / C3-1~C3-6 / C10 信息展示 | 依赖状态反馈 + 死代码清理 + 元数据保留 |
| **待定（机制/跨插件）** | C2-3 ffmpeg 构建偏好（需外壳支持）/ C9 拖拽（需外壳桥接） | 涉及外壳机制，按"先定机制必要性"原则单独决策 |

## 六、结论

convert 插件 v0.5.0 机制层面健康，**无 P0**。最值得立即做的三项：
1. **C1-1 wav 采样率**（一行修复，纠正无损语义）
2. **C7 原样提取音频**（补齐"任意音轨提取"的最后一块拼图：无损 + 快速）
3. **C2-2 probe 联动**（装完即反馈依赖状态，替代"转换时才炸"）

批 2 的压缩预设与 gif 参数化是承接"视频模块"主场景的自然延伸，建议与批 1 合并执行。
